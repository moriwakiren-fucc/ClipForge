# ClipForge

ClipForgeは、**iPadのSafariで使いやすい動画編集ワークスペース**です。動画・画像・音声をタイムラインへ配置し、再生、トリミング、分割、速度、変形、色調、キャプションを調整できます。現在はWebDevのフルスタック構成に対応し、ログインユーザーごとのプロジェクトと素材メタデータをデータベースで管理し、ファイル本体をS3互換ストレージへ保存します。

| 機能 | 内容 |
| --- | --- |
| 認証 | Manus OAuthのログイン状態を使い、未認証の素材保存を防止します。 |
| プロジェクト | ログインユーザーごとにプロジェクトを作成し、再訪時に選択できます。 |
| ファイルストレージ | 動画・画像・音声をS3へアップロードし、ファイルキーとメタデータをDBへ保存します。 |
| 編集 | 再生、スクラブ、IN/OUT調整、分割、複製、削除、速度・変形・色調・キャプションに対応します。 |
| 所有者制御 | 素材一覧・アップロード・削除はプロジェクト所有者のみに許可します。 |
| 書き出し | MediaRecorder対応ブラウザでは、選択した動画を端末へ簡易書き出しできます。 |

## 公開先の役割分担

**フルスタック版の公開先はWebDevホスティングです。** 認証、tRPC API、データベース、S3ストレージはサーバー実行環境を必要とするため、GitHub Pagesだけでは動作しません。完成版はWebDevの公開ドメインで利用してください。

**GitHub Pagesは静的版の公開先としてのみ利用できます。** リポジトリには静的フロントエンドをビルドするGitHub Actionsワークフローを残していますが、GitHub Pagesへデプロイした静的版ではログイン、プロジェクト保存、素材ストレージAPIは利用できません。GitHub Pages版は、ローカルブラウザ内の編集体験を確認するショーケース用途です。

## iPad Safariでの使い方

SafariでWebDev版を開き、ログイン後に**「素材」または「追加」**をタップして写真ライブラリまたはファイルから素材を選択します。読み込み時に素材本体はストレージへ送信され、プロジェクトと所有者に紐付けられます。保存済み素材は、ページを再読み込みしても素材一覧から復元されます。

素材を選択したら中央のプレビューと下部タイムラインで位置を決め、右側のインスペクターで調整します。狭い画面では、インスペクターを閉じて下部のモバイル操作バーから「素材」「分割」「文字」「出力」を使えます。

## ストレージ実装

ファイル本体はデータベースへ格納せず、`server/storage.ts` の `storagePut()` を通じてS3互換ストレージへ保存します。DBには `mediaAssets` テーブルの `fileKey`、`fileUrl`、ファイル名、MIMEタイプ、サイズ、長さ、所有者、プロジェクトIDを保存します。保存されたURLはWebDevの `/manus-storage/` 経由で配信されます。ストレージ層に削除APIがないため、削除操作では所有者確認後にメタデータ参照を除去します。

## 既知の制約

ブラウザからtRPCへBase64で送る方式のため、大容量動画はiPadのメモリと通信状況の影響を受けます。現在のアップロード上限は1ファイル250MBです。運用で長尺・4K素材を多用する場合は、次の段階で署名付き直接アップロードへ移行するのが適切です。音声ミックスや複数クリップを結合する長尺レンダリングも、別途レンダリング基盤が必要です。

## 開発・検証

`pnpm check` で型検査、`pnpm test --run` で認証とストレージAPIの境界テスト、`pnpm build` で本番ビルドを実行できます。フルスタック版のローカル開発は `pnpm dev` を使い、DB変更時はスキーマを編集して `pnpm drizzle-kit generate` を実行し、生成SQLを確認したうえで適用します。
